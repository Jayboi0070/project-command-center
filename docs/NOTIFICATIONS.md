# Notifications and alerts

## What you get
- **Push notifications** (even when the app is closed): reminder N minutes before a timed activity, an alert when it starts, an optional morning briefing and daily-review reminder. Controlled in Settings, Notifications.
- **Calendar alerts**: Schedule, "Calendar alerts" downloads an .ics file for the day. Open it to add the activities to your phone Calendar, with alerts 10 minutes before and at the start time. These are the most reliable alerts because the phone itself fires them.
- These are notifications, not an alarm clock. They follow your phone's silent/Focus settings. Use the Clock app for wake-up alarms.

## How it works
Browser (home-screen app) subscribes to push via the service worker (`frontend/sw.js`). The subscription is stored in `push_subscriptions`. An external scheduler calls `GET /api/push?action=tick&key=CRON_SECRET` every 10 minutes; the server finds due items in your time zone, claims each one in `notification_log` (so nothing is sent twice) and sends it with Web Push (VAPID).

## Vercel environment variables (backend)
| Name | Value |
|---|---|
| VAPID_PUBLIC_KEY / VAPID_PRIVATE_KEY | generated by `keys.html` (private key is secret) |
| VAPID_SUBJECT | `mailto:` + your email |
| CRON_SECRET | long random string (20+ chars), also used in the scheduler URL |

## Limits
- iPhone needs iOS 16.4+ and the app added to the Home Screen; notifications only work when opened from that icon.
- Timing is approximate: with a 10-minute scheduler a reminder can be up to ~10 minutes late.
- Neon's free plan has a monthly compute allowance. A scheduler keeps the database awake part of the day. Check Neon, Usage after a few days. If the allowance is running out, lengthen the interval or restrict it to active hours.
- Only activities with a start time get reminders. Completed activities are skipped.
- The tick URL contains the secret and may appear in logs. It can only trigger your own notifications. Rotate CRON_SECRET if you think it leaked.
- Delete `frontend/keys.html` and `frontend/js/keys.js` after generating keys.
- Push delivery has been verified here only up to the API calls (simulated browser); the real delivery through Apple/Google is first proven by the Send test button.
